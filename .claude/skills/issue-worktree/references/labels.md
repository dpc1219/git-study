# 라벨 체계

이름·색·설명의 원본은 `scripts/ensure_labels.py`다. 라벨을 바꾸려면 그 파일을 고친다.

## 유형 (이슈당 정확히 1개)
| 라벨 | 쓰는 경우 | 브랜치 접두사 |
| --- | --- | --- |
| `기능` | 새 분석·기능 추가 | `feat/` |
| `버그` | 오류·잘못된 결과 수정 | `fix/` |
| `문서` | README·가이드 | `docs/` |
| `개선` | 기존 분석·코드 성능/품질 향상 | `feat/` |
| `리팩터링` | 결과 변화 없는 구조 정리 | `refactor/` |
| `질문` | 논의·확인 | `docs/` |

## 주제 (0~2개)
| 라벨 | 요청문 키워드 |
| --- | --- |
| `노선분석` | 노선, 운영 성과, 배차, 회전율 |
| `정류장·OD` | 정류장, OD, 승하차, 환승 |
| `시간대수요` | 시간대, 첨두, 수요 패턴 |
| `데이터품질` | 결측, 미태그, 보정, 이상치, 검증 |
| `이용자행태` | 이용자, 요일·연령 패턴, 이용 빈도 |
| `데이터준비` | 더미 데이터, 원천 데이터, 전처리 |

매핑이 애매하면 주제 라벨 없이 진행한다. 새 주제 라벨을 임의로 만들지 않는다.

## 진행 상태 (정확히 1개, 교체 방식)
`상태:대기` → `상태:진행중` → `상태:리뷰중` → `상태:완료`

- 스킬이 이슈를 만들 때는 워크트리도 같이 만들므로 `상태:진행중`으로 시작한다.
- 상태 전환: `gh issue edit <번호> --remove-label "상태:진행중" --add-label "상태:리뷰중"`

## 기존 영문 라벨
`enhancement`, `bug`, `documentation` 등 GitHub 기본 라벨은 삭제·수정하지 않는다. 스킬은 한글 라벨만 쓴다.
