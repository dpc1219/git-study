# data-commit: 데이터 분석 조직용 커밋 그룹핑·메시지 작성

변경 파일을 **성격별로 묶어** 컨벤션에 맞는 커밋 여러 개로 나눈다.
분석 조직에서는 코드·원천 데이터·산출물(csv/xlsx/그래프)·문서가 한 번에 바뀌는 일이 흔하다.
이를 한 커밋에 섞으면 "코드 로직이 바뀐 것"과 "결과 파일이 재생성된 것"을 구분할 수 없어 리뷰와 재현이 어려워진다.
그래서 유형별로 나누고, 메시지에는 **무엇을 분석했고 왜 바꿨는지**가 드러나게 한다.

컨벤션 상세(타입 표, 스코프, 본문 규칙, 예시)는 `references/convention.md`에 있다. 메시지를 쓰기 전에 읽는다.

## 절차

1. **현황 파악**
   - `git status --short`, `git diff --stat`, `git diff --cached --stat`로 범위를 확인한다.
   - 이미 staged 된 항목이 있으면 사용자가 의도한 것일 수 있으니 임의로 unstage하지 않고 계획에 반영한다.
   - 분류 보조 스크립트를 쓰면 빠르다:
     `python .claude/skills/data-commit/scripts/group_changes.py` (옵션 `--range A B`로 과거 커밋 구간 분석 가능)
     결과는 경로·확장자 기반의 **초안**이다. 내용을 보고 판단이 필요한 파일은 `git diff <파일>`로 직접 확인해 그룹을 고친다.

2. **스타일 확인**
   - `git log --format=%s -15`로 이 저장소의 실제 메시지 형식(구분자 모양, 언어)을 본다.
     기존 이력이 컨벤션과 다르면 **기존 이력의 형식을 우선**하되 타입 체계는 컨벤션을 따른다. 이력이 없으면 `references/convention.md`의 기본 형식을 쓴다.

3. **그룹핑**
   - 1차 기준은 **변경 유형**(타입), 2차 기준은 **분석 주제**(스코프)다. 예: `time_demand.py` 신규 추가와 `time_demand` 산출물 csv 생성은 서로 다른 커밋 후보다.
   - 한 파일은 하나의 그룹에만 속한다. 한 파일에 서로 다른 성격의 변경이 섞였으면 `git add -p`로 쪼갤지 사용자에게 묻는다(자동으로 쪼개지 않는다).
   - 산출물이 해당 스크립트를 **방금 새로 만들면서 처음 생성된 것**이고 양이 많지 않다면 코드와 한 커밋으로 묶어도 된다. 판단 기준: 코드 리뷰어가 산출물까지 같이 봐야 의미가 통하는가.
   - 커밋 순서는 의존 방향을 따른다: 환경/설정 → 데이터 → 코드 → 산출물 → 문서.

4. **계획 제시 후 확인**
   커밋은 이력에 남고 되돌리기 번거로우므로, 실행 전에 표로 보여주고 확인받는다.

   | # | 메시지 | 파일 |
   | --- | --- | --- |

   사용자가 수정 요청하면 반영한다. "알아서 해줘" 등 명시적 위임이 이미 있으면 확인 없이 진행해도 된다.

5. **커밋 실행**
   - 그룹마다 `git add -- <파일들>`로 **경로를 명시**해 stage하고 커밋한다. `git add .`/`-A`는 다른 그룹 파일이 섞이므로 쓰지 않는다.
   - 메시지는 HEREDOC로 넘겨 줄바꿈·한글이 깨지지 않게 한다.
   - 시스템이 지시한 attribution(Co-Authored-By 등) 줄이 있으면 본문 끝에 붙인다.
   - 훅이 실패하면 원인을 고쳐 새 커밋으로 다시 시도한다(`--no-verify`, `--amend` 금지).
   - **push는 하지 않는다.** 사용자가 요청할 때만 한다.

6. **마무리**
   `git log --oneline -n <생성 개수>`와 `git status --short`로 결과를 보여주고, 남은 변경이 있으면 이유를 설명한다.

## 주의할 점

- **민감 데이터**: 개인 식별 가능 정보(카드번호, 이름, 연락처 등)가 담긴 원본 데이터, `.env`, 키·토큰이 stage 대상에 있으면 커밋하지 말고 사용자에게 알린다. 교통카드 같은 개인 이동 이력은 가명처리 여부를 먼저 물어본다.
- **대용량·바이너리**: 수십 MB 이상 파일이나 압축·DB 파일은 Git 대신 DVC/공유 스토리지를 검토하도록 한 줄 안내한다. 강제하지는 않는다.
- **노트북(.ipynb)**: 셀 출력이 포함돼 diff가 크다. 코드 변경이면 `feat/fix`, 출력만 갱신이면 `result`로 분류하고, 출력 제거(`nbstripout`)를 권장할 수 있다.
- **임시·캐시 파일**(`__pycache__`, `.ipynb_checkpoints`, `~$*.xlsx` 등)은 커밋 대상에서 제외하고 `.gitignore` 추가를 제안한다.
- 변경이 한 종류뿐이면 억지로 쪼개지 말고 커밋 하나로 끝낸다.
